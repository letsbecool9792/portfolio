**`letsbecool9792` — near-uncontested.** Nobody else owns that string. Page 1 is already all your own profiles (itch.io, LeetCode, X). The site wasn't ranking because it wasn't *indexed*, not because it was outranked. Phase 0 alone should win this within 2–6 weeks of indexing.

## Established facts (don't re-litigate)

- Canonical host is the **apex**: `suparno.me`. `www` 308s to it. Vercel-side config, not Namecheap.
- DNS is at **Namecheap BasicDNS** (`dns1/dns2.registrar-servers.com`). All records live in Namecheap → Domain List → Manage → **Advanced DNS**. Vercel does *not* manage them. Don't switch nameservers.

- **Googlebot renders this SPA fine.** Live tests return the fully-painted mobile tree on Landing *and* on a Journey chapter whose prose came from a runtime fetch. Prerendering is an optimization, not a rescue.
- Bluesky handle is the domain itself (`@suparno.me`), verified by an `_atproto` TXT record. The old `letsbecool.bsky.social` handle was released and no longer resolves.

## Phase 1 — per-route metadata & prerendering

Reordered after the render tests: head tags moved ahead of prerendering, because Google applies canonicals and titles *after* rendering, so tags alone already work for it. Prerendering's remaining job is social scrapers (which never run JS), speed, and independence from Google's deferred render queue.

- [x] **1a — content JSON to build-time imports.** Moved `public/*.json` → `src/content/*.json`; fetch-hooks became plain exports (`JOURNEY`, `PROJECTS`, `EXPERIENCE`, `SIDE_QUESTS`, `journeyStory()`). Removes a request waterfall and the dead loading states, and is the prerequisite for prerendering. Content still rides in each page's lazy chunk, so the entry bundle is unchanged.
- [ ] **1b — per-route head tags.** React 19 hoists `<title>`/`<meta>`/`<link>` natively, no react-helmet. Per-route title, description, canonical, OG. *Currently one shell serves all 12 routes, so there is deliberately no `rel=canonical` and no `og:url` anywhere — either would point the whole site at the homepage.*
- [ ] **1c — prerender.** `vite-react-ssg` keeps Vite + the existing route table. `useIsMobile`'s server snapshot returns `true`, so the static HTML is the mobile tree — which is what mobile-first indexing wants.
- [ ] **1d — real 404s.** Every unknown URL currently returns HTTP 200 with the SPA shell (soft 404s across the entire unknown URL space).

## Phase 5 — performance (deliberately last)

Core Web Vitals is a tiebreaker between near-equal results. You are not in that regime for either query. Fix these because you want a fast site, not because they'll win you the name.

- [ ] **Fonts** — `src/index.css` opens with five chained Google Fonts `@import`s, a serial render-blocking waterfall (CSS → 5 more CSS → font files). Move to `preconnect` + one combined `<link>`, or self-host.
- [ ] **Landing desktop LCP is ~2.6s by construction** — the `<h1>` sits behind `initial={{opacity:0}}` with a 1.8s delay. Mobile drops the entrance, and Google measures mobile, so this is milder than it looks.
- [ ] `Cache-Control` for `/assets/*` (unhashed, so repeat visits revalidate more than needed).
- [ ] WebP conversion.
- [ ] 🟡 Delete the unused `public/vite.svg`.

## Verification tools

| Tool | For |
|---|---|
| [Search Console](https://search.google.com/search-console) | Indexing, sitemap, live render tests |
| [Rich Results Test](https://search.google.com/test/rich-results) | Structured data as Google parses it. Person isn't a rich-result type, so "No items detected" is expected — look under *Other items* |
| [validator.schema.org](https://validator.schema.org) | Schema correctness. `@graph` nodes referenced by `@id` get **inlined** into the referencing node, so Person appears nested inside WebSite rather than as a second top-level item. That's correct, not a bug |
| [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) | OG card. Caches hard — hit **Scrape Again** after any change |
| [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/) | Same, for LinkedIn |
| X card validator | Dead — Twitter removed it. Post the link somewhere quiet and look |

`fb:app_id` and `og:url` warnings in the Facebook debugger are both ignorable: you have no Facebook app, and `og:url` is omitted on purpose until 1b.
